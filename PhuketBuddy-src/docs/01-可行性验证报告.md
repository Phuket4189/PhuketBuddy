# PhuketAI 桌面气泡 — 可行性验证报告

> 验证对象：`https://ai.pukitcore.com`（PhuketAI · AI API Gateway）
> 验证时间：2026-10-26 · 验证方式：真实网络请求 + 前端产物静态分析
> 结论先行：**数据获取可行（高置信度）**，无需浏览器自动化，纯 HTTP 即可完成登录、余额、用量、API Key 的读取；主要风险在「非官方契约的字段漂移」和「凭据本地保管」。

---

## 1. 结论摘要

| 能力 | 可行性 | 依据 |
|---|---|---|
| 账号登录（邮箱+密码） | ✅ 可行 | `POST /api/v1/auth/login` 返回 401 `INVALID_CREDENTIALS`（说明已进入账号校验，未被人机验证拦截） |
| 会话保持 / 自动续期 | ✅ 可行 | 存在 `POST /api/v1/auth/refresh`（空 body 返回字段校验错误，证明路由存在） |
| 余额读取 | ✅ 可行 | 用户对象含 `balance`；另有 `/usage/dashboard/stats`、`/user/profile`、`/user/platform-quotas` |
| 用量（今日/区间/趋势/模型分布） | ✅ 可行 | `/usage/dashboard/stats`、`/usage/dashboard/trend`、`/usage/dashboard/models`、`/usage?page=…` |
| API Key 管理 | ✅ 可行（读）/ ⚠️ 写需联调 | `/keys`、`/keys/stats`、`/keys/usage`、`/user/api-keys/{id}/usage/daily` |
| 桌面端直接跨域调用 | ❌ 不可行（浏览器内） | 响应无任何 `Access-Control-*` 头，`OPTIONS` 预检返回 **403** |
| 原生客户端直接调用 | ✅ 可行 | 请求/响应均为标准 JSON，服务端未做 UA/Referer 强校验，无反爬拦截 |

**一句话结论：这个需求可以做，而且难度不高——难的不是取数，而是把「桌宠」的窗体行为（透明、吸边、置顶、托盘）做扎实。**

## 2. 站点架构判定

| 项 | 实测值 |
|---|---|
| 前端 | Vue 3 + Vite SPA（`/assets/index-DQqGPygH.js`，`window.__APP_CONFIG__` 注入） |
| 后端 | Go + Gin（错误体 `Key: 'LoginRequest.Email' Error:Field validation…` 为 gin binding 特征） |
| 入口服务器 | `nginx/1.28.3 (Ubuntu)`，**非 Cloudflare 代理**（`server` 头暴露源站） |
| 安全头 | CSP、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin` |
| API 根 | `https://ai.pukitcore.com/api/v1` |
| 时区 | `Asia/Shanghai`，站点版本号 `production-native56-20261025` |

> ⚠️ 注意 `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'`：**不能**用 iframe 把站点嵌进桌面壳里取数，必须走 API。

## 3. 鉴权链路（已实测）

### 3.1 登录

```http
POST /api/v1/auth/login
Content-Type: application/json

{ "email": "…", "password": "…" }
```

实测响应：

| 场景 | HTTP | 响应体 |
|---|---|---|
| 空 body | 400 | `Key: 'LoginRequest.Email' … 'Password' failed on the 'required' tag` |
| 错误账号 | 401 | `{"code":401,"message":"invalid email or password","reason":"INVALID_CREDENTIALS"}` |
| 无 token 访问受保护接口 | 401 | `{"code":"UNAUTHORIZED","message":"Authorization header is required"}` |
| 伪造 token | 401 | `{"code":"INVALID_TOKEN","message":"Invalid token"}` |

成功时（据前端代码 `br()` 反推）返回：

```json
{ "access_token": "…", "refresh_token": "…", "expires_in": 3600, "user": { … } }
```

前端将它存到 `localStorage` 的 `auth_token / refresh_token / auth_user / token_expires_at`，并在 `Authorization: Bearer <access_token>` 中携带 → **同一套 Bearer 方案在原生客户端完全可复刻。**

### 3.2 关键发现：登录环节没有验证码

站点公开配置 `GET /api/v1/settings/public` 返回：

```json
{
  "turnstile_enabled": false,
  "tencent_captcha_enabled": false,
  "aliyun_captcha_enabled": false,
  "totp_enabled": false,
  "passkey_enabled": false,
  "login_agreement_enabled": true,
  "login_agreement_mode": "modal",
  "balance_low_notify_enabled": true,
  "balance_low_notify_threshold": 0.5,
  "site_name": "PhuketAI",
  "api_base_url": "https://ai.phuketcore.com",
  "version": "production-native56-20261025"
}
```

即：**没有人机验证、没有 2FA、没有 Passkey**，邮箱密码即可换取 token。这是"能做成小软件"的决定性前提。

### 3.3 会话续期与条款

- `POST /api/v1/auth/refresh`，body `{"refresh_token":"…"}`（空 body → 400 校验错误，确认存在）。
- 站点启用了登录协议：若接口返回 `423 USER_AGREEMENT_REQUIRED`，需 `POST /api/v1/user/agreement/accept`。首次登录需处理这条分支，否则会卡在"登录成功但取不到数"。

## 4. 数据接口清单（均以 401 证明路由存在）

> 探测方法说明：Go/Gin 对已注册但需鉴权的 GET 路由返回 **401**，对未注册路由返回 **404**，因此可在无账号情况下精确区分「存在」与「不存在」。

### 4.1 账户与余额

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/auth/me` | 当前用户（含 `balance`） |
| GET | `/api/v1/user/profile` | 用户资料 |
| GET | `/api/v1/user/platform-quotas` | 分平台额度（`[{platform, …}]`） |
| GET | `/api/v1/billing/statement` | 账单流水 |
| GET | `/api/v1/announcements` | 公告 |

### 4.2 用量

| 方法 | 路径 | 参数 |
|---|---|---|
| GET | `/api/v1/usage/dashboard/stats` | —（一次拿齐概览） |
| GET | `/api/v1/usage/dashboard/trend` | `start_date,end_date,granularity=day\|hour` |
| GET | `/api/v1/usage/dashboard/models` | `start_date,end_date` |
| GET | `/api/v1/usage/dashboard/snapshot-v2` | 聚合快照 |
| POST | `/api/v1/usage/dashboard/api-keys-usage` | `{api_key_ids:[…]}` |
| GET | `/api/v1/usage` | `page,page_size,api_key_id` |
| GET | `/api/v1/usage/stats` | `period=today\|…` 或 `start_date,end_date` |

### 4.3 API Key

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/keys` | Key 列表 |
| GET | `/api/v1/keys/stats` | Key 维度统计 |
| GET | `/api/v1/keys/usage` | Key 维度用量 |
| GET | `/api/v1/user/api-keys/{id}/usage/daily` | 单个 Key 近 N 天用量（`days=30`） |
| — | 新增/编辑/删除 | ⚠️ 需真实账号联调确认方法（推测 POST/PUT/DELETE `/keys[/{id}]`） |

### 4.4 字段（由前端渲染逻辑反推）

- **user**：`id, email, role, balance, balance_notify_enabled, balance_notify_threshold, balance_notify_extra_emails`
- **dashboard stats**：`today_requests, total_requests, today_actual_cost, total_actual_cost, total_api_keys, by_platform[]`
- **key**：`id, name, key, quota, status, expires_at, group`
- **usage 记录**：`model, prompt_tokens, completion_tokens, total_tokens, cost, group, status_code, latency, created_at`
- **计量单位**：服务条款明确「**1 credits = 1 元人民币**」，站内统一用 `credits` 记账。

## 5. 实测证据

```
GET  /                                    → 200 text/html, 66,465 bytes
GET  /api/v1/settings/public              → 200 {code:0,…}   ← 无需鉴权
GET  /api/v1/model-plaza                  → 200 {…}          ← 无需鉴权
GET  /api/v1/auth/me                      → 401 {"code":"UNAUTHORIZED",…}
GET  /api/v1/usage/dashboard/stats        → 401 (存在)
GET  /api/v1/keys                         → 401 (存在)
POST /api/v1/auth/login  {}               → 400 字段校验
POST /api/v1/auth/login  {错误账号}       → 401 INVALID_CREDENTIALS   ← 关键：未触发验证码
POST /api/v1/auth/refresh {}              → 400 字段校验 (存在)
OPTIONS /api/v1/auth/login                → 403  ← 无 CORS，浏览器跨域必挂
```

响应头摘录（能说明"没有 CORS"）：

```
server: nginx/1.28.3 (Ubuntu)
content-type: application/json; charset=utf-8
（无 access-control-allow-origin / allow-headers / allow-methods）
```

## 6. 风险清单与对策

| # | 风险 | 等级 | 对策 |
|---|---|---|---|
| 1 | **接口非公开契约**，站点升级可能改字段/改路径 | 中高 | ① 用 `settings/public.version` 做版本探测；② 解析全部「缺字段不崩」；③ 失败降级为"打开网页查看"；④ 关键字段双通道（`/auth/me` 与 `/usage/dashboard/stats` 互为兜底） |
| 2 | 浏览器跨域被禁 | 高 | 客户端必须用**原生 HTTP 栈**（WPF `HttpClient` / Tauri Rust 侧 / Go），不能在前端页面里 fetch |
| 3 | 密码与 token 落盘 | 高 | Windows DPAPI 加密（`ProtectedData`，绑当前用户），存 `%APPDATA%`；不写日志；退出可"清除登录" |
| 4 | 登录条款 423 闸门 | 中 | 识别 `USER_AGREEMENT_REQUIRED`，弹窗引导到浏览器接受条款，再自动重试 |
| 5 | 风控（`risk_control_enabled: true`） | 中 | 固定正常 UA、请求频率 ≥ 60s/次、仅面板打开时拉明细；遇到 429 指数退避 |
| 6 | 站点无 SLA / 可能停服 | 低 | 本软件定位"仪表盘"，不代理任何模型调用，停服不影响用户正常用站 |
| 7 | 用户改密码 / 令牌失效 | 低 | 401 → 静默 refresh → 仍失败则气泡进入"需重新登录"态，不弹错误堆栈 |
| 8 | 账号安全合规 | — | 凭据只在本机；不提供"多人共用一份凭据"的云端同步 |

## 7. 尚未验证、需要真实账号的部分

以下只影响**字段级实现**，不影响可行性判断：

1. 登录成功响应的完整 JSON（`user` 对象的全部字段）。
2. `/usage/dashboard/stats` 的实际字段名与数值口径（预估 vs 实际）。
3. `/keys` 的写操作（新增/编辑/删除）方法、body 与权限限制。
4. token 实际有效期（`expires_in`）与 refresh 是否轮换。
5. 是否存在登录频率/异地风控策略。

> 建议：进入开发后第一步用真实账号跑一次「登录 → 抓 4 个接口 → 打印字段树」的联调脚本（只落盘字段结构，不落盘数值），30 分钟内即可把这些全部确认。
